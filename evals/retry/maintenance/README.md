# 订单客户端维护：多次独立对照

这次任务提供 [已有模块](starter.py)与[接口和调用方约束](task.md)，要求同时修复分页查询及创建订单。保持三组条件：任务本身、任务加六技能、再加原候选经验；不根据分数改答案或验收。

| 任务 | 正常行为与边界 |
|---|---|
| `list_orders` | 跨页共用总预算、部分结果不冒充完整结果、空页与空字符串游标继续读取、游标编码与循环检测、Retry-After、内层重试和调度延迟 |
| `create_order` | 正常创建、同键同正文重放、键过期后停止重放、保护调用者数据、保留超时后的未知状态、不吞掉本地异常 |

[验收器](checks.py)先于正式生成固定，共 31 个场景；参考实现必须通过，已有坏代码必须在关键场景失败。独立核对修正了“把合法额外等待误判”“丢弃空字符串游标”等评分器问题，修正均发生在模型生成之前。仍使用确定性传输器，不连接真实订单服务，也不声称覆盖并发或真实网络的所有行为。

## 准备与独立生成

在仓库根目录运行：

```bash
python -B evals/retry/run.py self-check
python -B evals/retry/run.py prepare --suite maintenance --trials 3 \
  --out /tmp/order-maintenance-1 --model YOUR_MODEL \
  --effort YOUR_EFFORT --harness YOUR_AGENT
```

准备器保存公共任务、starter、六技能、原候选经验、验收器与运行器的内容哈希，以及三份原始提示。`manifest.schedule` 在每轮轮换组别顺序；每个位置用一个新会话独立生成，共 9 次。相同模型、推理档位、宿主和资源限制保持一致，不共享历史、其他候选或验收源码。它仍是上下文对照，不是让代理实际运行完整六节点。

每次保存原始输出为 `baseline-1.py` 等文件；编号是试验位置，不是重试到成功的次数。仅去除最外层代码围栏，不改代码。如果调用失败，保留失败状态和一份不能通过的占位模块，不用成功输出替换它；候选缺失则整次评分拒绝，避免静默遗漏。

可在投递前和首次观察到最终回复时记录时间：

```bash
python -B evals/retry/run.py stamp --run /tmp/order-maintenance-1 \
  --arm baseline --trial 1 --event start
# 用相同配置的新会话生成该组提示，保存原始输出。
python -B evals/retry/run.py stamp --run /tmp/order-maintenance-1 \
  --arm baseline --trial 1 --event finish
```

`observed_turn_seconds` 是从投递前到收到完成消息的周转耗时，包含工具投递、排队、并发竞争及观察延迟，不是纯生成时间。若宿主能给出实际 token、生成耗时或结算费用，可在对应 `.metrics.json` 记录并补充来源；缺失值保持 `null`。费用或耗时不能填负数、NaN 或无穷。只要有一次费用未知，整组费用总额也未知；共同的经验提炼、工具构建、验证维护成本另行记录，不能忽略后宣称总成本收益。

## 评分与阅读结果

先审阅生成代码只使用约定回调，再评分所有 9 份候选：

```bash
python -B evals/retry/run.py grade --run /tmp/order-maintenance-1 \
  --output /tmp/order-maintenance-1/report.json
```

验收逻辑、源材料和发送提示必须保持准备时的版本。评分后修复自己的实现可以作为后续开发，但不能覆盖本轮模型候选。若确认评分器有缺陷，应另开版本、说明原因并重跑全部条件，不能只改某一组标准。

- **独立生成数**：每组 3；重复评分同一文件不增加次数。
- **整次通过率**：同一候选的两个任务都通过，分母每组为 3。
- **任务通过率**：每个函数通过其全部用例才算该任务通过，分母每组为 6。这 6 个结果来自 3 份代码，不能视为 6 次独立生成。
- **场景通过率**：每组 3×31=93，仅用于定位边界；不是 93 个独立模型样本。失败报告保留对应轨迹。
- **耗时与费用**：逐次测量与聚合同时保留，标明测量覆盖率；评分耗时只叫 `grade_wall_seconds`。无完整成本数据时不评价省钱。

进程崩溃或超时按该候选全部任务与场景失败计入。运行器仍使用 5 秒子进程限制、空工作目录和精简环境；这不是 OS 安全沙箱，只运行审阅过的候选。CI 只执行免费自检，不发起模型调用。
