# 接口失败与重试：最小对照评测

后续的[订单客户端维护套件](maintenance/README.md)增加了已有实现、两个调用方及每组三次独立生成；原 2026-10-24 数据保持不变。当前运行器使用 schema 2，历史 schema 1 结果请使用 [881097e 提交](https://github.com/Wfyywj/agent-skills/commit/881097e75f15ea676dea6196a370b2c7444e80c3)的原运行器复现，不修改历史 manifest 来迁就新版。

这个试点执行模型生成的 Python 重试函数，检查调用次数、超时预算、结果未知和重复副作用。它比较同一个任务在三种上下文下的代码生成结果：

| 条件 | 给执行模型的材料 |
|---|---|
| `baseline` | [同一份任务说明](task.md) |
| `workflow` | 任务说明 + 仓库六个核心技能原文 |
| `experience` | 前一组材料 + [有限重试候选经验](../../experiences/retry-safety.md) |

模型版本、推理档位、宿主和生成次数保持相同；每组使用新会话，不共享答案或历史。这是**技能上下文的对照**，没有逐阶段执行六节点，也不测完整项目交付能力。公共宿主指令仍会影响三组，不把 baseline 称为完全没有系统指令的模型。

## 免费自检

仅需 Python 3.11+ 标准库，在仓库根目录运行：

```bash
python -B evals/retry/run.py self-check
```

[基础验收代码](checks.py)仍包含 3 个开发用例和 17 个留出用例；`self-check` 还会检查新增的维护套件。手写参考实现必须通过；盲目重试、无实际执行却直接报成功等错误策略必须被拒绝。这个结果只证明评测器的这些检查能工作，不能冒充模型成绩。

CI 只运行这项免费自检和原有格式/链接检查，不自动调用模型。虚拟时钟不需要真实等待，故障传输器不访问网络；这不验证真实 HTTP 栈或业务幂等实现。

## 生成一次三组试验

```bash
python -B evals/retry/run.py prepare --out /tmp/retry-trial-1 \
  --model YOUR_MODEL --effort YOUR_EFFORT --harness YOUR_AGENT
```

输出目录必须是新的。准备器固定任务、六技能、经验及验收代码的内容哈希，并生成三份 `*.prompt.txt`；评分时会核对这些实际提示文件，原件必须保留。

分别将三份提示交给同一配置的模型，在三个新会话中各生成一次代码。只提供指定提示，不让执行模型读取验收程序、参考实现、已有候选或其他组输出。保存原始代码为同目录下的 `baseline.py`、`workflow.py`、`experience.py`；只可去掉外层代码围栏，不为提高分数修改候选。失败尝试也要保留，不能换一份成功输出后冒充第一次生成。

提示准备与验收是可运行命令，模型调用由操作者使用已有宿主完成，没有新增模型 SDK 或账号依赖。manifest 中的模型信息依赖如实填写，脚本不能证明外部宿主使用了指定模型。各组的时间、token、费用和共同的经验提炼/工具构建/维护成本能取得就记录，不能取得就保留 `null`，不能当成零。

## 执行行为验收

先检查候选代码仅使用给定回调，没有文件、网络等额外操作，再运行：

```bash
python -B evals/retry/run.py grade --run /tmp/retry-trial-1 \
  --output /tmp/retry-trial-1/report.json
```

报告路径必须不存在，以免覆盖历史。每组在临时工作目录的新进程内执行，清除继承的环境变量，并有 5 秒进程超时。这**不是操作系统安全沙箱**，不要在有敏感数据的机器上执行未审查的第三方代码。

schema 2 报告给出每次生成的开发/留出通过数、整项任务结果、代码哈希和失败轨迹，以及跨次汇总；成功场景保留 ID，可重放取得完整计数。候选超时或崩溃会按该候选全部用例失败计入，不丢弃；候选缺失或源材料变化则拒绝整次评测。`grade` 退出 0 表示三组已评分，不表示三组都通过，候选是否通过应读取报告。`grade_wall_seconds` 仅是本地验收耗时，不是模型生成耗时或总成本。

留出用例只是同一接口约定下的新故障组合，没有提供给生成会话；它们在公开仓库中可见，不能声称长期保密或代表独立真实项目。需要重复生成时使用新的目录和会话；重复评分同一份代码不算多次模型试验。源材料改动后应开启新试验，历史复现则检出对应提交，不能修改旧 manifest 来通过快照检查。
