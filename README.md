# agent-skills

六个小而独立的 AI 开发技能：从一句话需求到代码、验证和 CI 交付。支持仅前端、仅后端或前后端协作。

每个技能只有一份 `SKILL.md`，可以单独使用，也可以由主代理按下面的流程串联。技能说明判断和行动，实际执行复用目标项目的工具；没有额外调度器、运行时或付费服务依赖。

## 六个节点

| 技能 | 解决什么问题 | 交给下一步的结果 |
|---|---|---|
| [clarify-task](skills/clarify-task/SKILL.md) | 先查现状，补齐影响实现的需求条件 | 目标、范围、验收条件与未决事项 |
| [plain-plan](skills/plain-plan/SKILL.md) | 用简单的话说明最小改动与理由 | 涉及位置、实现思路与验证办法 |
| [implement-slice](skills/implement-slice/SKILL.md) | 完成一个可独立验收的代码切片 | 代码差异、对应需求与已做检查 |
| [verify-change](skills/verify-change/SKILL.md) | 执行适用检查，区分通过与未验证 | 验收结果、命令与证据 |
| [review-change](skills/review-change/SKILL.md) | 只读审查必要性、正确性与漏改 | 确认问题、待核实项与验证缺口 |
| [deliver-change](skills/deliver-change/SKILL.md) | 授权内提交并核对最终代码的 CI | 代码或 PR、CI 结果和剩余限制 |

`plain-plan` 保留原有内容，也能单独用于改写难懂的方案。

## 安装与独立使用

在支持 Agent Skills 的工具中，将所需技能目录放入该工具的技能位置。也可以让代理显式读取某个 `SKILL.md`，不用安装全部六个。

例如在 macOS 的 Codex 中，首次获取后复制到个人技能目录：

```bash
git clone https://github.com/Wfyywj/agent-skills.git
mkdir -p ~/.codex/skills
cp -Rn agent-skills/skills/. ~/.codex/skills/
```

`-n` 会跳过已有同名文件；升级时先比较差异再合并，避免覆盖自己的修改。只安装一个技能时，把最后一行换成：

```bash
cp -Rn agent-skills/skills/clarify-task ~/.codex/skills/
```

在 Codex 中可以按名字调用；其他宿主按其调用方式使用：

```text
$clarify-task 给订单页增加导出，先明确范围和验收，不写代码。
$plain-plan 把这份需求写成简单易懂的方案，说明现有能力、本次只改什么。
$implement-slice 按已确认的方案完成导出按钮，本次只改前端，复用已有接口。
$verify-change 验证当前改动，按项目约定执行相关检查，不修改业务代码。
$review-change 审查当前未提交差异，结合需求只报告有依据的问题。
$deliver-change 汇总当前改动和验证结果，本次只做本地交付，不提交或推送。
```

每个技能都可以从用户请求和仓库补齐输入，不要求先运行前一个技能，也不依赖其他技能的文件。没有仓库、运行工具或必要权限时，应说明缺口，不能虚构检查结果。

## 串成一次开发

主代理按 **clarify-task → plain-plan → implement-slice → verify-change → review-change → deliver-change** 执行。失败或确认问题返回相应实现步骤，修复后重验受影响部分；业务目标变化则返回澄清和方案步骤。

一个需求有多个切片时，逐个完成实现、验证和审查，记录已覆盖与剩余的验收条件；全部约定范围完成后再交付，不能把第一个切片做完当成整个需求完成。

已明确的需求无需再访谈，已有且仍适用的方案和检查结果可以复用。独立调用只完成该技能的工作；只有用户要求完整开发时才继续串联，不把一次审查自动扩大成实现和发布。

可以把下面这段交给能读取本仓库的代理，替换尖括号里的内容：

```text
读取 agent-skills/README.md，按六节点工作流完成：<需求>。
目标仓库：<路径>；范围：<仅前端 / 仅后端 / 全栈>。
遵守目标项目约定，保留已有改动；允许修改相关代码和执行项目允许的检查。
完成后提交并推送到 <远端>/<分支>，核对该提交的必需 CI；不合并或部署。
先查代码，只有关键业务条件无法自行确认时才问我；已有授权不要重复询问。
```

不需要发布代码时，把交付授权改成“只做本地交付，不提交或推送”。技能文件不会自动执行：主代理需要实际读取对应技能、调用可用工具并核对结果。

### 接力只传必要信息

小任务在对话里保留一段记录即可；需要换模型或恢复会话时，复用现有任务文档保存，不强制新增多份文件：

```text
目标与范围：要改变的行为、明确不做的事。
验收与约束：可观察结果、项目约定和已有授权。
当前版本与改动：仓库、分支、提交，以及相关未提交差异。
当前结果：已完成 / 需返工 / 受阻；已通过、失败、未验证的内容及证据。
下一步：下一节点、待解决的问题或缺少的条件。
```

主代理在每个节点结束时更新这段信息，作为下一节点的输入；不要要求技能重复输出所有字段。恢复时重新核对最新代码和差异；旧版本的验证不能自动用于新改动。

### 按实际开发范围走

- **仅前端**：使用现有接口或明确的 mock，核对页面行为；mock 通过不等于真实联调通过。
- **仅后端**：验证接口、权限、数据和受影响调用方，不额外建设页面或强制浏览器验收。
- **全栈**：先对齐字段、错误和权限，再分切片实现与联调；依赖稳定且写入路径不冲突时才并行。

交付时区分“代码已提交”“本地检查通过”“CI 通过”。没有 CI、无权读取或必需任务未成功时，明确保留未验证状态；本地交付也不应声称完成了 CI 验收。

## 验证范围与来源

这套技能不绑定模型厂商，但读取技能、执行工具和实际交付效果是三件事，不能据格式兼容承诺任意模型效果相同。新技术栈优先沿用目标项目的版本和工具，不自动安装调研中的候选项目。

[开源调研与选型依据](docs/research/2026-10-23-fullstack-workflow.md)保留当时的来源与取舍；本 README 描述当前实现。技能为独立编写，没有复制第三方脚本或引入其运行时。
